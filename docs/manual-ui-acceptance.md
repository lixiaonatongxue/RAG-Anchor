# 人工浏览器验收清单

本文件用于在真实浏览器中验收“Chunk 检索 → PDF 证据高亮”、“证据展示问答 → 引用跳转”、可选的“AI 生成问答 → 引用校验”，以及可选的“多语言语义检索 → 引用定位”。

当前自动化测试覆盖 API client、坐标转换、请求竞态、引用 span 转换、问答模式与错误提示、语义候选/索引失效/引用定位，以及后端问答/定位正确性。**本文件中的浏览器步骤不等于已自动执行**。本次开发环境未安装浏览器自动化工具，因此没有声称完成浏览器验收。

后端已用本机 Ollama `qwen3:8b` 完成少量真实联调，但本文件中的浏览器步骤仍未执行。Mock Provider 的自动化测试与本机少量联调均不代表更广泛的生成质量；浏览器验收需在可用环境中手工完成。

## 最短可执行验收路径（约 10 分钟）

以下步骤覆盖本轮新增的「完整句子支持区间」和 Ollama 真实生成。准备一份包含可检索句子（建议含 `stages` 或中文关键词）的 PDF。

1. 启动后端、前端与 Ollama，并按 C 节设置 `RAG_ANCHOR_LLM_ENABLED`、`RAG_ANCHOR_LLM_BASE_URL`、`RAG_ANCHOR_LLM_MODEL=qwen3:8b`、`RAG_ANCHOR_LLM_REASONING_EFFORT=none`。
2. 上传 PDF，确认左侧列表出现该文档并被自动选中。
3. 点击「建立索引」，确认状态为「已索引」并显示页数与 Chunk 数。
4. 在 Chunk 检索输入关键词（例如 `stages`），提交后确认结果列表出现页码与字符区间。
5. 切换到「AI 生成回答」，输入文档中可回答的问题（例如「项目有哪些阶段？」），检索关键词填写文档原文词句，提交。
6. 确认回答区域标注 AI 生成、引用编号为 `E1/E2…`，且回答与引用均来自当前文档。
7. 检查引用卡片：应显示「支持句」或「仅检索命中」。前者是命中词所在完整句子，后者表示句子边界不可靠时仅定位原关键词；两者都不代表模型结论已被事实验证。
8. 点击引用：应跳到对应页并高亮卡片所示的区间；「支持句」高亮整句，「仅检索命中」只高亮关键词，且没有第二个阅读器或按文字重新搜索。
9. 使用缩放、翻页再返回：高亮随 viewport 重新计算，位置不漂移。
10. 分别执行以下异常场景：输入无命中关键词（明确拒答且不调用模型）、停止 Ollama 后提交生成（显示服务错误且不展示模型文本）、连续快速提交两个问题（只保留最后一次回答）。

完成以上步骤后，在文末「验收记录」中如实填写；未实际执行时不得标记为通过。

## 前置条件

1. 后端已启动：`cd backend && UV_LINK_MODE=copy uv run uvicorn rag_anchor.main:app --port 8000`
2. 前端已启动：`cd frontend && npm run dev`
3. 准备一份可直接选中文字的 PDF，建议满足：
   - 至少 2 页；
   - 同一页有重复文字；
   - 有一条跨行文字；
   - 包含一个可字面检索的关键词（例如 `quick`）。
4. 如有中文 PDF，另准备一份包含中文关键词的样本，用于验证非 ASCII 文本。
5. 如验收语义检索，需本机 Ollama 已安装 `bge-m3`（`ollama list` 可见），并设置 `RAG_ANCHOR_EMBEDDING_ENABLED=true`、`RAG_ANCHOR_EMBEDDING_BASE_URL`、`RAG_ANCHOR_EMBEDDING_MODEL=bge-m3`；未安装时只执行 D 节的错误路径，不下载模型。

## A. Chunk 检索与证据高亮（阶段 A）

- [ ] 上传 PDF 后，文档出现在左侧列表并被自动选中。
- [ ] 点击「建立索引」，状态变为「已索引」，显示页数与 Chunk 数。
- [ ] 输入仅在文档中存在的字面关键词，点击「检索」；结果列表显示页码与字符区间。
- [ ] 点击第一条结果：PDF 跳到对应页，命中位置高亮并滚动到视口中央。
- [ ] 点击第二条结果：新高亮替换旧高亮，不同 occurrence 的矩形位置不同。
- [ ] 跨行证据显示多个行矩形，不是一个覆盖整段的合并大框。
- [ ] 缩放、翻页后再回到命中页，高亮位置随当前 viewport 正确重算。
- [ ] 快速连续点击不同命中：最终显示最后一次点击的命中，旧请求不覆盖新状态。
- [ ] 快速切换文档：旧文档的检索/定位结果不出现在新文档下。
- [ ] 原「证据搜索」面板（M0）仍可检索、跳转、高亮，行为未回归。
- [ ] 关闭后端后执行检索：界面显示错误提示，不显示伪造的成功结果。
- [ ] 人为制造索引与 PDF 不一致（索引后替换后端存储的 PDF 文件），点击结果应显示“这条证据暂时无法可靠定位”，且不生成近似高亮。

## B. 证据展示问答与引用（默认模式）

- [ ] 选中并索引文档后，问答模式选择器默认显示「证据展示（不调用语言模型）」，「提问」按钮可用。
- [ ] 输入自然语言问题，并在「检索关键词」中填写文档原文词句；点击「提问」。
- [ ] 回答区域明确显示“证据展示模式 · 未接入语言模型”，不出现“模型生成”的表述。
- [ ] 引用列表显示 `E1`、页码、支持区间和原文片段；区间标注为「支持句」或「仅检索命中」，且全部来自当前文档。
- [ ] 点击引用：使用 `evidence/locate` 返回的矩形跳转并高亮；「支持句」高亮完整句子，「仅检索命中」只高亮关键词。两者与 A 使用同一套高亮路径，不因支持区间扩大而额外绘制近似矩形。
- [ ] 输入不存在的关键词：界面明确显示无法依据文档回答，引用为空，不生成猜测性答案。
- [ ] 问题留空或未建立索引：提问按钮禁用或显示明确提示。
- [ ] 对两个内容相同的文档分别提问：引用始终属于当前选中的文档。
- [ ] 快速连续提交两个问题：最终只显示最后一次问题的回答，旧响应不覆盖新回答。
- [ ] 问答进行中切换文档：旧文档的回答不显示到新文档。
- [ ] 索引后替换后端 PDF 再点击引用：显示 409 对应的“这条证据暂时无法可靠定位”，不重新搜索文字、不画近似矩形，旧高亮不残留为当前引用。
- [ ] 关闭后端后点击提问：显示连接失败错误，不显示伪造的答案或引用。
- [ ] 问答结果区域只以纯文本渲染原文，不执行 PDF 内容中的 HTML 或指令。

## C. AI 生成问答（可选模式）

前置：后端已设置 `RAG_ANCHOR_LLM_ENABLED=true`、`RAG_ANCHOR_LLM_BASE_URL` 与 `RAG_ANCHOR_LLM_MODEL`，且模型服务可用。未部署模型时，只执行第 1–3 项。

- [ ] 未配置模型时切换到「AI 生成回答」并提交：显示“AI 生成模式尚未配置或未启用”的明确错误，不出现伪造的生成答案或引用；可切回证据展示模式继续使用。
- [ ] 模式选择器在请求进行中禁用，请求结束后恢复。
- [ ] 切换模式会清空上一模式的答案与引用，旧请求响应不会覆盖新状态。
- [ ] 已配置模型时提交问题：按钮显示「生成中…」，完成后回答区域标注“AI 生成回答 · 引用编号由服务端校验，结论仍需人工核对原文”。
- [ ] 回答中的引用编号只对应本次检索返回的 `E1`、`E2`…；页码、支持区间与文本来自服务端，不来自模型文本。
- [ ] 点击生成回答的引用：仍通过 `evidence/locate` 跳转并高亮；「支持句」或「仅检索命中」标记与证据展示模式一致，没有第二个阅读器，也不按文字重新搜索或估算坐标。
- [ ] 模型服务超时：显示超时错误，不展示模型文本；服务返回错误或输出无法校验时同样不展示伪造答案。
- [ ] 问题没有字面命中时，生成模式直接返回拒答，不调用模型。
- [ ] 请求进行中切换文档或重新索引：旧回答不显示到新文档/新索引。
- [ ] 浏览器 Network 面板中请求体始终是 `POST /qa`，没有额外的模型 HTTP 请求；模型调用只发生在后端。

## D. 多语言语义检索（M2-01，可选）

前置：后端已设置 `RAG_ANCHOR_EMBEDDING_ENABLED=true`、`RAG_ANCHOR_EMBEDDING_BASE_URL` 与 `RAG_ANCHOR_EMBEDDING_MODEL=bge-m3`，`ollama list` 中存在该模型，且 `GET /api/tags` 能返回其 digest。未部署 embedding 模型时，只执行第 1、2、8 项。

- [ ] 上传并索引一份含英文原文的 PDF（例如 “The project has three stages: ingestion, retrieval, and evidence verification.”）。
- [ ] 点击「建立语义索引」，完成后显示模型名、维度、候选数量、索引/候选版本与建立时间。
- [ ] 将检索方式切换为「语义」，提交中文问题（例如「这个项目有哪些阶段？」）。
- [ ] 结果引用来自英文原文，标注为「语义候选」并显示相似度；不使用检索关键词输入框。
- [ ] 点击引用：仍通过 `evidence/locate` 跳转并精确高亮候选原文区间，没有第二个阅读器、不按文字重新搜索、不估算坐标。
- [ ] 切换回「关键词」：原字面检索与默认行为不变。
- [ ] 未建立语义索引就选择「语义」：提交按钮禁用或提示先建立语义索引，不发生自动字面回退。
- [ ] 未配置 embedding 或模型不可用时建立语义索引：显示明确错误（未启用/超时/服务失败），不显示伪造结果。
- [ ] 重建字面索引后再次语义提问：提示语义索引已失效（409），需重新建立语义索引。
- [ ] 修改 `RAG_ANCHOR_EMBEDDING_MODEL_VERSION` 后再次语义提问：提示版本不一致（409），不静默使用旧向量。
- [ ] 同名模型 tag 指向不同 digest（例如重新 pull/替换模型）后再次语义提问：提示模型身份变化（409）；`GET /api/tags` 不可用或模型缺少 digest 时显示明确错误，不回退、不当作未变化。
- [ ] 语义问答进行中点击「重建语义索引」：旧回答/引用被清除且重建完成前不能提交；重建完成或失败后可以重新提问，旧响应不会恢复旧引用。
- [ ] AI 生成回答 + 语义检索组合：回答引用仍为服务端校验的 `E1/E2…`，失败时不展示模型文本。
- [ ] 快速连续提交两个问题或切换文档：只保留最后一次响应，旧引用不出现在新文档下。
