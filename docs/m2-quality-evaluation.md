# RAG-Anchor M2 质量评测报告

- 日期：2026-11-01
- 适用基线：`main` @ `f952915`（Unicode 定位修复之后）
- 评测对象：M2-01 多语言语义检索与可追溯问答、B1 选择器实验、B2 上下文补全实验、首轮真实 PDF 探索评测
- 结论性质：**特定模型、特定数据集、单次固定回归与首轮探索结果，不是生产质量保证**

> 本报告只记录已经实际执行过的评测。M2-02 的 5 道真实 PDF 题仍为 exploratory，标签未冻结；不得把本报告中的任何数字当作通用准确率、正式 benchmark 或生产 SLA。

## 结论摘要

- **M2-01**：在 42 条固定合成集（v2.1）上，语义检索 Query-level Recall@5 为 29/29、相关跨度召回 39/40；生成严格干净 19/29，不可回答拒答 13/13，46/46 引用通过编号、原文与定位校验。检索指标明显好于生成质量。
- **B1**：v2.1 相关跨度召回从 39/40 提升到 40/40，但 42 条中只有 1 条明确改善；真实 A/B 只有 3 题、单模型、单次运行，生产默认仍为 `legacy`。
- **B2**：467 字符同页论证补全成功，但上下文噪声增加、收益有限，未通过质量验收；代码已归档在仓库外，不是当前产品功能。
- **Unicode 定位**：legacy 路径的 UTF-16 代理对映射缺陷已修复，真实样本恢复精确定位，API 与 PDF 坐标契约不变。
- **真实 PDF 探索**：2 篇英文论文 + 2 份中文技术 PPT、首批 5 道探索题；事实完整覆盖 3/5、严格跨度 2/5。标签未冻结，不是正式 benchmark。

## 1. 系统目标与核心技术链路

RAG-Anchor 的目标是让 PDF 中的回答**可追溯、可定位、可人工核对**：检索与引用必须回到存储的原文切片，最终高亮必须来自 PDF 的真实字符几何，而不是根据答案文本重新搜索或绘制近似框。

```text
PDF 上传与阅读
      ↓
文本提取与 Chunk 索引（页面文本、Chunk、Python 字符偏移）
      ↓
字面检索 / 可选语义检索
      ↓
（可选）Qwen 生成：服务端分配证据编号，模型只返回结构化 claims 与引用编号
      ↓
引用校验：编号、文档归属、原文切片、支持区间全部由服务端重建
      ↓
PDF 精确定位：Python span → PDFium 字符区间 → 逐行矩形
      ↓
前端 PDF.js 高亮；定位失败时显式报错，不绘制近似框
```

### 1.1 已实现的核心能力

- **文档接入**：PDF 上传、列表、详情、删除、原始文件读取；磁盘文件名只由 UUID 派生。
- **文本与索引**：`pypdfium2` 抽取页面文本，确定性切分 Chunk，持久化页面文本、Chunk 与索引元数据；建立/重建索引是单事务原子替换。
- **字面检索**：在已索引 Chunk 中做字符串检索，返回 Python 字符串偏移；不返回几何坐标。
- **语义检索（可选，M2-01）**：`bge-m3` embedding + SQLite 内派生向量索引 + 余弦 Top-K。索引记录模型名与 digest、向量维度、候选切分版本、源指纹等；过期或模型变化时返回 409，不回退到字面检索。
- **问答（可选生成）**：`answer_mode = evidence_only`（默认，不调用模型）或 `grounded_generation`；`retrieval_mode = literal`（默认）或 `semantic`。服务端分配 `E1`、`E2`…，模型的页码、偏移、Chunk ID、文档 ID 和几何字段一律忽略；引用字段由服务端从存储原文重建。
- **引用校验**：无证据时两种模式都固定拒答；未知引用编号、非法 JSON、空 claim 等按 502 拒绝；模型未启用/未配置返回 503；超时返回 504。结构合法只证明“陈述关联到真实证据”，**不证明事实蕴含**。
- **精确定位**：`evidence/locate` 把 Python span 映射为 PDFium 字符区间，再用 `get_charbox()` 生成逐行矩形；坐标是 absolute PDF user space（ADR-0001）。无法精确映射时返回 409，不伪造矩形。
- **前端**：原生 TypeScript + Vite + PDF.js；支持上传、阅读、命中高亮、引用点击定位、字面/语义检索切换、证据展示/AI 生成模式切换与请求失效处理。

### 1.2 工程边界

- 单文档检索与问答；不做跨文档、多轮对话、OCR、扫描件理解。
- 不做 Agent、reranker、查询改写、专利专项检索、事实蕴含验证。
- 不引入外部向量数据库或 ANN；语义检索是单机 SQLite 派生向量上的暴力余弦 Top-K。
- 生成与语义检索都通过 HTTP 调用外部模型服务，默认关闭；字面检索与 `evidence_only` 可完全离线运行。
- 仓库不包含模型权重、推理框架或 GPU 代码。

### 1.3 M0–M1 基线

M0–M1 已建立可复现的合成 PDF 锚点评测基线：用独立于 PDFium 的布局真值检查命中数、页码、逐行矩形和坐标契约。该基线验证的是锚点几何契约，不等于真实 PDF 的通用质量；详细口径见 [benchmark-audit.md](benchmark-audit.md)。

## 2. M2-01 固定合成集回归（数据集 v2.1）

### 2.1 数据集与运行条件

- 数据集：`backend/evaluation/semantic_dataset.json`，名称 **`m2-01-multilingual-retrieval-labels-v2.1`**。
- 规模：**42 条问题 = 29 条可回答 + 13 条不可回答**。
- 覆盖：中文问题召回英文证据、英文改写、跨页证据、部分相关候选、同关键词干扰、相似主题不同结论、不可回答、Recall@5 与 Top-1 分歧。
- 标签在运行 embedding 前按存储原文固定；不可回答问题不进入 Recall@K 分母，单独统计候选误召回与拒答。
- 模型与配置：`bge-m3` 做 embedding，`qwen3:8b` 做生成；最低余弦分数 `0.30`；最终引用上限 5；单次固定回归。
- 性质：**合成数据、单模型、单次运行**；0.30 是当前配置，不是已验证的最佳阈值。

### 2.2 检索结果

| 指标 | 结果 | 说明 |
|---|---:|---|
| Query-level Recall@5 | **29/29 = 1.0** | 29 条可回答问题的相关证据均进入最终 Top-5 |
| 相关跨度 Recall@5 | **39/40 = 0.975** | 40 条标注相关跨度中命中 39 条 |
| 完整覆盖查询 | 28/29 = 0.9655 | 至少一条相关跨度未完整进入 Top-5 |
| Top-1 正确率 | 0.8276 | 5 条问题的 Top-1 排序错误 |
| 不可回答问题有候选 | 13/13 | 拒答不是靠阈值实现，而是模型固定拒答 + 引用校验 |
| 502/504 | 0/42 | 本轮无 HTTP 502/504 |

未召回的 1 条 span 是跨页场景中的“500 页”证据；它在 Top-10 比较中排第 7，仍未进入 Top-5。Top-10 只多召回这 1 条相关句，同时新增 149 条非相关候选，因此生产候选数仍为 5、阈值仍为 0.30。

### 2.3 生成与引用结果

| 指标 | 结果 | 说明 |
|---|---:|---|
| 可回答生成带引用答案 | 28/29 | 1 条误拒答 |
| 不可回答固定拒答 | **13/13** | 0 条误答、0 条引用 |
| 引用总数 | 46 | 全部来自服务端重建 |
| 引用通过 ID、原文重建与 PDF 定位 | **46/46** | 34 条落在标注相关句，12 条在标注之外 |
| 严格干净答案 | **19/29** | 辅助逐条复核口径，不是人工事实认证 |
| 超出问题范围 | 7/29 | 引用真实但不回答所问 |
| 不完整 | 2/29 | 必要事实未覆盖 |
| 误拒答 | 1/29 | 有证据但未作答 |

**如何解读：**

- “Query-level Recall@5 = 1.0”只说明在这 42 条固定合成问题上，检索把至少一条相关证据放进了 Top-5；它不代表相关跨度全部召回，也不代表答案完整。
- “46/46 引用通过校验”只证明引用编号合法、原文切片可重建、PDF 可定位；它**不证明**引用支持回答，也不证明回答事实正确。
- 19/29 严格干净、7/29 过度回答、2/29 不完整、1/29 误拒答，说明检索指标不能替代生成质量。生成遗漏、过度回答和对象绑定仍需独立处理。
- 这些数字来自一次固定回归，不能外推为生产准确率，也不是正式 benchmark。

## 3. B1 实验：同页近邻证据选择（`neighbor_v1`）

### 3.1 设计动机

生产默认 `legacy` 直接取语义排序的前 `max_citations` 条候选。相关证据可能刚好排在 Top-5 之外，尤其是在跨页、多证据问题中。B1 尝试用“同页近邻”把一条高相关但排序稍低的证据拉进最终集合，同时保持所有偏移、原文和引用重建路径不变。

### 3.2 `legacy` 与 `neighbor_v1` 的区别

| 项目 | `legacy`（生产默认） | `neighbor_v1`（内部实验） |
|---|---|---|
| 候选池 | 直接使用排序结果 | `min(20, 3 × 引用上限)` 的更大候选池 |
| 选择规则 | 取前 N 条 | 保留全局 Top-1；至多加入一条同页、不重叠、与 Top-1 分差 ≤0.10 的近邻；其余按原排序补齐；重叠跨度跳过 |
| 是否改写偏移 | 否 | 否，只对已验证候选做子集选择 |
| 是否暴露为 API 字段 | 否 | 否；只能通过构造参数或测试入口显式启用 |
| 生产默认 | 是 | 否 |

`neighbor_v1` 是纯函数、确定性的，只重排和子集化已经校验过的候选，不生成文本、不修正 offset。

### 3.3 固定合成集覆盖改善

在 v2.1 标签、同一候选池、同一分数、同一阈值 0.30、同一最终上限 5 的条件下：

| 指标 | legacy | B1 `neighbor_v1` | 差异 |
|---|---:|---:|---:|
| 相关跨度召回 | 39/40 = 0.975 | **40/40 = 1.0** | +1 |
| 完整覆盖查询 | 28/29 = 0.9655 | **29/29 = 1.0** | +1 |
| Query-level Recall@5 | 29/29 | 29/29 | 0 |
| Top-1 变化 | — | — | 0 |
| 不相关跨度 | 47 | 47 | 0 |
| 有标签回归 | — | — | 0 |
| 集合发生变化的查询 | — | — | 2 条（1 条明确改善，1 条指标中性） |

改善集中在跨页“500 页”证据：B1 把它从 Top-5 之外拉入最终集合。42 条查询中只有这 1 条明确改善，因此收益面很窄。

### 3.4 三组真实生成 A/B 结论

同一批候选、同一 Prompt、同一模型参数，对 3 道合成问题各跑 legacy 与 B1，共 6 次真实 Qwen 请求：

- **A 组（上传限制）**：B1 把“500 页”证据带入 Top-5，模型实际引用并输出了正确事实；legacy 缺少该证据。这是唯一一条“选择改变直接改善答案”的证据。两种模式都仍带入了标签判为不相关的“预览 10 页”事实。
- **B 组（删除生命周期）**：两种模式的选择集合完全相同。模型遗漏了已在 Top-5 中的个人导出证据，并把已覆盖内容写成“未覆盖”。这是生成遗漏，选择器无法修复。
- **C 组（中文审计内容）**：两种模式的选择集合完全相同。模型引用了真实但不回答“包含哪些信息”的保留期限。这是过度回答，选择器同样无法修复。

共同结论：**证据进入 Top-5 ≠ 模型会使用；模型引用 ≠ 回答正确/切题；引用 ID 合法 ≠ claim 得到支持。** B1 只能修复“相关证据没有进入最终集合”，不能修复生成遗漏或过度回答。

### 3.5 5 道真实 PDF 问题的选择对照

在 4 份真实文档上的首轮 5 道探索题中，legacy 与 B1 的最终选择集合 **5/5 完全相同**：0 道改善、0 道退化。原因不是选择器失效，而是这 5 题的同页近邻本来就在 legacy Top-5 内，或 Top-1 所在页在候选池中只有一条候选；缺失证据的排名远在 Top-15 之外。主要瓶颈在候选池/查询召回，不在最终 5 条的排序。

该结果进一步说明：B1 的适用面有限，而且这 5 题本身仍是 exploratory。

### 3.6 为什么生产默认仍保持 `legacy`

1. 42 条中只有 1 条改善，收益面太窄。
2. 数据集是合成的，真实 A/B 只有 1 个模型、3 道题、单次运行，没有多轮方差或独立人工评分。
3. 同页近邻是启发式规则，可能在其它版面优先带入同页弱相关句子；当前负样本不足。
4. B 组和 C 组暴露的是生成侧问题，切换选择器无法解决。
5. 只有在更大规模、多文档、多语言、多版面的独立对照中同时满足“无标签回归、改善可复现、真实答案质量提升”后，才值得讨论切换默认。

因此 B1 保留为实验性策略，生产默认继续 `legacy`，未改变任何外部 API 行为。

## 4. B2 负面实验结果：同页上下文补全（`context_window_v1`）

### 4.1 设计目的

B2 在 B1 的基础上尝试把同一页、同一 Chunk 内只隔空白的相邻候选合并为一个窗口（最多补 2 个相邻句、单窗口 ≤500 字符），使最终引用跨度与模型实际看到的文本一致，而不是只引用一句。

### 4.2 文本层面的成功

真实 PDF 探索题中的一道频域损失函数问题，其三句论证在文本层面被完整补全：窗口为 467 字符，与人工标注跨度完全一致，字面搜索也能命中。这说明“同页同 Chunk 只隔空白”的合并规则在目标案例上是可行的。

### 4.3 为什么仍不通过质量验收

- **上下文噪声增加**：补全把页眉、页码、相邻 bullet 等不必要内容带入引用；C1-Q1 的窗口从 227 字符扩到 298 字符，其中 246 字符在标注之外。
- **引用数量下降**：总引用数从 25 降到 21；噪声窗口从 17 降到 15 主要来自引用总数下降，而不是噪声精度提高。
- **收益有限**：严格 span 完整数从 5 提到 7，契约有效口径只从 5 提到 6；除目标案例外，仅 C1-Q2 多覆盖 1 条严格 span，其余问题没有严格覆盖提升。
- **目标案例当时不可定位**：该 467 字符窗口与原始 legacy seed 都触发了补充平面字符的定位缺陷；该缺陷后来由独立提交修复。即使修复后窗口可以定位，B2 的噪声与有限收益问题仍然存在，质量结论不变。
- **副作用明确**：引用条数减少、上下文变长，但没有足够收益抵消契约和噪声风险。

### 4.4 当前状态

- **不建议保留或启用** `context_window_v1`。
- B2 是实验，不是当前产品功能；生产默认仍是 `legacy`。
- 实验代码已安全归档在仓库外；当前工作区不包含 B2 代码，也未提交到 Git。

## 5. Unicode 精确定位修复

### 5.1 缺陷不是 B2 引入的

在 B2 实验期间发现目标窗口无法通过 `evidence/locate`。随后用真实 `EvidenceLocationService.locate` 路径复现，确认**原始 legacy seed 同样失败**。因此这是既有定位路径的缺陷，不是 B2 新引入的破坏；修复范围也没有混入任何 B2 代码。

### 5.2 根因

- Python 字符串偏移以 **Unicode 码点**计数；PDFium 字符索引以 **UTF-16 code unit** 计数。
- 补充平面字符在 PDFium 中由高、低两个代理项码元组成；`get_text_range(i, 1)` 对两个码元分别返回空串，而整页提取会把代理对解码为一个 Python 字符。
- 旧的逐单元拼接无法复现存储页面文本，导致定位在进入坐标计算前就失败；即使绕过检查，span 之前的补充字符也会让后续字符索引整体偏移。

### 5.3 修复方式

- 在构建偏移映射时识别合法的 UTF-16 高低代理对，解码为一个 Python 字符，并把低代理项标记为 continuation。
- 起点跳过不产生文本的单元（包括前一个补充字符的低代理项）；终点保留属于已包含补充字符的低代理项，但不越过真正无文本的单元。
- 边界落在无法精确表达的字符内部、或区间内部包含真正无文本单元时，继续显式失败，不返回近似范围。
- 没有使用字符串 `replace`、Unicode 归一化或固定偏移补偿来掩盖问题；没有伪造字符矩形。

### 5.4 修复结果

- 真实 PDF 样本的 legacy seed（159 字符）恢复定位，返回 2 个真实矩形。
- B2 的 467 字符窗口恢复定位，返回 5 个真实矩形（仅作为兼容性观察，未继续 B2 开发）。
- 补充平面字符本身可以定位，两个代理项码元返回同一真实字符框，按行合并后只输出一个矩形，不重复、不外扩。
- 普通英文、中文、重音字符、重复命中、多页、CropBox、旋转、CRLF 多矩形等既有测试未回归。
- 修复提交时验证：47 项 `evidence_service` 定向测试、775 项完整后端测试通过；`ruff`、`uv lock --check`、`git diff --check` 通过。
- **API 字段、Python 偏移语义、PDF user-space 坐标、CropBox/rotation 契约均未改变**；`char_start` 的变化是正确的 PDFium 索引空间换算。

修复已合入 `main`（提交 `f952915`）。

## 6. 首轮真实 PDF 探索评测

### 6.1 范围

- 语料：**2 篇英文论文 + 2 份中文技术 PPT**（PPT 是技术演示文稿，**不是专利**）。
- 问题：首批 **5 道探索题**，覆盖频域损失函数选择、实验硬件与数值、实体数量、会议论文统计、图谱规模等类型。
- 标签状态：**Draft，未冻结**。这是 exploratory 评测，**不是正式 benchmark**，不能据此推断整体准确率。

### 6.2 结果

| 指标 | legacy | B1 `neighbor_v1` |
|---|---:|---:|
| 事实完整覆盖 | 3/5 | 3/5 |
| 严格跨度完整覆盖 | 2/5 | 2/5 |
| 选择集合变化 | — | 0 增 0 删（5/5 相同） |
| Top-1 变化 | — | 0/5 |
| 无关候选（25 条中） | 17 | 17 |

- 缺失证据主要是硬件型号、具体数值、不同页面的补充论证；这些候选的排名远在 Top-15 之外，说明瓶颈在候选池/查询召回，而不是最终 5 条的排序。
- 25/25 已选择候选通过了**当时采用的原文检查**：`page_text[start:end] == source_text` 成立，且 `search_anchors(..., match_case=True)` 能命中对应页。该检查不是后来逐一执行的 `evidence/locate` 几何契约检查。
- 本轮未调用生成模型，因此没有这 5 题的真实生成评测结论；只做检索选择与原文检查。
- 该 5 题不能写成正式 benchmark；其余 7 道真实问题标签也仍是 Draft。

## 7. 已知限制

1. **复杂多证据召回不完整**：跨页、多实体、数值与条件同时出现的问题仍可能漏掉必要证据；候选池和查询召回是主要瓶颈。
2. **已有证据仍可能被生成模型遗漏**：证据已经进入 Top-5，模型仍可能不使用，甚至把已覆盖内容写成“未覆盖”。
3. **过度回答**：模型可能引用真实但不回答所问的事实，引用合法不代表切题。
4. **引用可定位不等于事实蕴含**：服务端只校验引用编号、原文切片和 PDF 定位，不验证 claim 与证据之间的事实支持、对象绑定或完整性。
5. **中文专利专项验证尚未完成**：当前没有针对中文专利文献的专项检索、术语、权利要求或说明书结构评测。
6. **真实标签未冻结**：首轮 5 道真实 PDF 探索题是 Draft；其余 7 道真实问题标签也仍是 Draft。
7. **浏览器场景未完成全部人工验收**：快速连续提问、模型故障、语义索引失败等浏览器场景尚未全部人工执行；自动化测试不能替代真实浏览器验收。
8. **评测规模有限**：M2-01 是 42 条合成数据的单次固定回归；B1 真实 A/B 只有 1 个模型、3 道题、单次运行；真实 PDF 探索只有 5 题。所有数字都不能外推为生产准确率。
9. **能力边界**：不包含 Agent、reranker、专利专项检索、事实蕴含验证、OCR、跨文档检索或多轮对话；不引入外部向量数据库。
10. **B1/B2 状态**：B1 保留为内部实验，生产默认 `legacy`；B2 未通过质量验收，代码已归档在仓库外，不是当前产品功能。
